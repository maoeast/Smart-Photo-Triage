The coverage-gate closure added six observable Windows identity-bound deletion error/recovery
fixtures. The pre-add baseline was 1378 / 1431 lines (96.296296%) and 454 / 484 branches
(93.801653%). The final focused run is 151 passed, with both independent 95% gates met.

The 128 tests cover default dry-run, explicit execution, complete mutation-time preflight under the
lock, durable state-boundary recovery, no-overwrite finalization, safe existing-target semantics,
COPY and MOVE resume, source and target replacement races, bundles, live/dead/unknown lock owners,
malformed lock retention, bounded doctor diagnosis, rollback ownership, and actual CLI flows.

The independent audit added thirteen RED cases for mutation-time plan, bundle, capacity,
writability, global transaction and path drift; durable MOVE deletion states and commit failures;
target/source races; and all-or-nothing bundle rollback preflight. The exact focused run became
`13 passed, 84 deselected in 3.09s`. Four follow-up RED cases for prepared-state target revalidation,
quarantine no-overwrite, unsupported hard links, and bounded doctor scanning became
`4 passed, 97 deselected in 0.54s`.

MOVE commits its deterministic quarantine path and source identity before mutation, then records
prepared, quarantined, unlinked, and removed states independently. It hashes the source before the
last final-target identity/hash verification and source unlink. A same-hash pre-existing MOVE target
is recorded as unowned but does not cause a false `ALREADY_PRESENT` completion. Rollback restores
the source while leaving that unowned target untouched.

Every transaction and journal state boundary uses its own SQLite commit with `synchronous=FULL`.
Normal exceptions reload current durable journal metadata before writing `FAILED`, so a later error
cannot erase partial or target ownership established by an earlier committed boundary.
