# Smart-Photo-Triage 本地 GUI 操作手册

适用版本：`1.2.1`。本手册同时说明面向普通用户的 Windows 桌面版和高级用户的本地浏览器 GUI。

## 先选择运行方式

| 方式 | 适用对象 | 启动与端口 | 目录选择 |
| --- | --- | --- | --- |
| **Smart Photo Triage 桌面版** | 普通 Windows 用户 | 双击开始菜单或桌面图标。内部使用随机 `127.0.0.1` 端口，关闭窗口即停止。 | Windows 原生文件夹对话框 |
| **`spt gui` 浏览器模式** | 高级用户、自动化、Agent | 默认 `127.0.0.1:8765`，可用 `--port 0` 自动选择。以 `Ctrl+C` 关闭。 | 手动输入完整路径 |

两种方式都只监听 IPv4 loopback，绝不开放 LAN 或远端访问。桌面版需要 Microsoft Edge WebView2 Runtime。缺失时会显示安装提示和官方下载链接。发布包目前未签名，SmartScreen 可能提示“未知发布者”。

## Windows 桌面版安装、启动与卸载

1. 运行发布的 `Smart-Photo-Triage-Setup-1.2.1.exe`，按安装向导完成安装。默认位置为 `%LOCALAPPDATA%\Programs\Smart Photo Triage`，可选择创建桌面快捷方式。
2. 从开始菜单或桌面打开 **Smart Photo Triage**。无需打开 PowerShell，也不需要处理端口。
3. 首次使用时依次选择独立的工作区、照片源和输出目录。点击“选择…”会打开 Windows 原生文件夹选择器。点击取消不会修改当前输入。
4. 直接关闭应用窗口即可结束本次本地服务。需要卸载时，进入 Windows“设置 > 应用 > 已安装的应用”，卸载 **Smart Photo Triage**。卸载不删除工作区、原始照片或输出副本。

若提示 WebView2 缺失，请安装 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) 后重新打开应用。

## 浏览器模式说明

Smart-Photo-Triage 是在本机前台运行的 Python 程序。执行 `spt gui` 后，它只监听
`127.0.0.1`，自动打开浏览器。本机以外的设备无法访问，也不会开机自启。

- **安装**：创建项目专用 Python 虚拟环境并安装程序。
- **启动服务**：在终端启动 GUI 进程。
- **停止服务**：在该终端按 `Ctrl+C`。
- **目录选择**：浏览器模式请手动输入路径。原生目录选择器只在桌面版提供。
- **卸载**：删除项目内的虚拟环境。运行工作区和照片目录不会因卸载程序而自动删除。

## 1. 安装

### 前置条件

- Windows 10/11。
- Python 3.11 或更新版本。用 `python --version` 检查。
- 首次安装需要能访问 Python 包索引以下载依赖；之后可在离线状态使用已安装的 GUI。
- 项目目录为 `F:\Projects\Smart-Photo-Triage`。

在 PowerShell 执行：

```powershell
Set-Location F:\Projects\Smart-Photo-Triage
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade "setuptools>=68" wheel
.\.venv\Scripts\python.exe -m pip install -e .
```

安装完成后可验证：

```powershell
.\.venv\Scripts\spt.exe --help
```

看到命令列表中包含 `gui` 即表示安装成功。

## 2. 启动、关闭与再次启动

### 推荐启动命令

```powershell
Set-Location F:\Projects\Smart-Photo-Triage
.\.venv\Scripts\spt.exe gui --workspace "D:\SPT-Workspace"
```

`F:\Projects\Smart-Photo-Triage` 是程序源码目录，`D:\SPT-Workspace` 是运行工作区，二者应分开。
工作区会保存扫描数据库、预览、人工审核决定、计划和事务日志。它不是照片输出目录。

正常情况下浏览器会自动打开。默认地址固定为：

```text
Smart Photo Triage GUI: http://127.0.0.1:8765/
```

如果浏览器没有自动打开，将该地址复制到本机浏览器即可。

### 可选启动参数

```powershell
# 改用其他端口。默认端口 8765 被占用时使用。
.\.venv\Scripts\spt.exe gui --workspace "D:\SPT-Workspace" --port 8765

# 不自动打开浏览器，只在终端打印地址
.\.venv\Scripts\spt.exe gui --workspace "D:\SPT-Workspace" --no-open
```

### 关闭 GUI

回到启动 GUI 的 PowerShell 窗口，按：

```text
Ctrl+C
```

这会停止本地 HTTP 进程及它打开的审核页面服务。它不会删除工作区、照片源或已复制的输出文件。

### 可选：让 `spt` 成为简写

每次打开新 PowerShell 时，先激活项目环境：

```powershell
Set-Location F:\Projects\Smart-Photo-Triage
.\.venv\Scripts\Activate.ps1
spt gui --workspace "D:\SPT-Workspace"
```

若 PowerShell 的执行策略阻止 `Activate.ps1`，不要修改系统策略，直接使用前述完整的
`.\.venv\Scripts\spt.exe` 命令即可。

## 3. 使用前的目录规划

建议准备三个不同的目录：

| 用途 | 示例 | 是否会被写入 |
| --- | --- | --- |
| 照片源 | `E:\Photo-Inbox` | 扫描、准备和审核阶段不会修改；本 GUI 的执行模式也不会移动或删除它 |
| 输出目录 | `E:\Photo-Organized` | 仅在“真正复制”成功后写入整理后的副本 |
| 工作区 | `D:\SPT-Workspace` | 保存数据库、缩略图、计划和事务日志 |

不要把工作区放在照片源或输出目录内部。实际使用也建议将输出目录设为照片源之外的独立目录，便于
确认输出容量和回滚范围。先用一小份可复制的测试照片完成一次完整流程，再用于正式照片库。

## 4. GUI 字段、按钮与推荐顺序

打开 GUI 后，页面底部的黑色结果框会显示每次操作的 JSON 结果或错误信息。每项操作按顺序执行，
不要跳过“审核”“批准”“预检”和“模拟执行”。

| 页面元素 | 作用 | 是否写入照片源/输出 |
| --- | --- | --- |
| **工作区** | 显示当前工作区；点击 **选择工作区** 打开本机目录选择器。选择后会初始化该目录的 SPT 工作区状态。 | 工作区会有状态写入 |
| **照片源** | 点击 **选择照片源** 打开本机目录选择器，也可手动输入。 | 否 |
| **输出目录** | 点击 **选择输出目录** 打开本机目录选择器，也可手动输入。 | 仅“真正复制”会写入 |
| **1. 扫描** | 读取文件清单、元数据并计算内容哈希，建立可追踪的媒体记录。 | 否 |
| **2. 准备与分析** | 生成本地预览和质量指标，识别精确重复/连拍组，并按已保存的 v1.2.1 Provider Route 生成初步标签。 | 照片源不写入；工作区会写预览、分析与路由审计记录 |
| **3. 审核** | 在新标签页打开本地人工审核页面。 | 仅保存人工审核决定到工作区 |
| **4. 计划** | 根据审核后的数据构建不可变的 **COPY** 整理计划，自动把 `计划 ID` 写回页面。 | 否 |
| **计划 ID** | 当前计划的唯一标识。后续批准、预检、模拟、执行都使用它。 | 否 |
| **5. 批准** | 把当前不可变计划标记为已批准，允许下一步预检。 | 仅工作区状态 |
| **6. 预检** | 核验计划、源文件状态、输出目录条件、空间和未完成事务等。预检失败时不能执行。 | 否 |
| **7. 模拟执行** | 在已通过预检的前提下模拟执行，验证结果而不复制文件。 | 否 |
| **8. 真实复制** | 对已批准且预检通过的计划执行复制。点击后会出现二次确认，确认后才会创建副本。 | **是，写入输出目录** |
| **诊断** | 只读检查锁、未完成事务、日志、临时文件和计划陈旧等状态。 | 否 |
| **复制记录编号** | 用于指定要回滚的已执行复制。 | 否 |
| **安全回滚** | 回滚指定复制创建的输出副本。填写复制记录编号后，点击按钮并在二次确认中确认。 | **是，删除该事务可验证的输出副本** |

### 推荐完整流程

1. 点击“选择照片源”和“选择输出目录”选择目录；也可输入完整路径。
2. 点击 **1. 扫描**，确认结果框没有错误。
3. 点击 **2. 准备**，等待预览、分组和离线初步分析完成。
4. 点击 **3. 审核**。在新标签页检查照片和初步分类后，保存人工决定。
5. 回到控制台页，点击 **4. 计划**，记录自动填入的计划 ID。
6. 点击 **5. 批准**，再点击 **6. 预检**。预检必须显示正常结果。
7. 点击 **7. 模拟执行**，确认目标路径和数量符合预期。
8. 仅在确认无误后，点击 **8. 真实复制**，并在弹出的二次确认中选择“确定”。
9. 在结果框记录执行结果中的 `transaction_id`。需要撤销本次复制时才使用它。

## 5. 配置大模型分析

日常整理请停留在首页“开始整理”。首页只显示本次会使用的模型和联网状态，不会占用空间展示完整配置。只有首次设置、切换模型或调整联网权限时，才点击顶部 **模型与隐私** 进入设置页。

### 支持范围

GUI 的“模型设置”使用 v1.2.1 统一兼容层，而不是 Gemini 专用表单：

| 提供方 | 是否联网 | 用途 |
| --- | --- | --- |
| **离线演示模型** | 否 | 默认选项。`FakeVisionProvider` 产生确定性的演示结果，用于测试完整工作流。 |
| **Google Gemini** | 是 | 使用 Gemini 原生图像接口。 |
| **OpenAI** | 是 | 使用 OpenAI 图像分析兼容接口。 |
| **Anthropic** | 是 | 使用 Anthropic Messages/Vision 接口。 |
| **DeepSeek** | 是 | 通过统一 OpenAI-compatible 接口接入。选择后自动填入官方服务地址；在 API 密钥框粘贴自己的 Key。 |
| **OpenAI-compatible** | 取决于 URL | 统一接入 Qwen、豆包、GLM 和本机 VLM 等兼容服务。 |

Codex、Claude Code 是开发 Agent，不是本工具中可直接填写 Key 的视觉 Provider。Anthropic API 由独立
Provider 驱动处理，不能把 Gemini、OpenAI 或 Anthropic 的 Key 混用。

### 在 GUI 中配置分析服务和模型使用方式

1. 在 **添加或修改分析服务** 填写“配置编号”“模型服务”和“模型名称”。配置编号仅供系统区分多个服务使用。
2. 选择 Gemini、OpenAI、Anthropic 或 DeepSeek 后，界面会自动填入对应的官方服务地址；兼容服务必须填写地址。系统会自动依据 URL
   判定 loopback、LAN 或 remote，并拒绝不安全的远程 HTTP 地址。
3. 在 **API 密钥** 粘贴服务商提供的实际 Key，然后点击 **保存分析服务**。密钥会与当前 Windows 用户和这台电脑绑定保存，下次启动会自动可用，页面不会显示 Key 内容。
4. 点击 **保存分析服务**。右侧“已添加的分析服务”会显示服务类型、模型、网络范围和访问密钥是否已准备。
5. 在 **单张照片分析** 和 **连拍照片复核** 分别选择优先模型、模型临时不可用时使用的备用模型，以及可选的一次
   “把握不足时改用更强模型”，然后点击 **保存模型使用方式**。
6. 如配置了互联网模型服务，展开“允许连接模型服务（默认关闭）”，勾选互联网权限，输入 `ALLOW_CLOUD` 后保存。局域网模型服务
   同理，需要输入 `ALLOW_LAN`。未授权时 Router 会阻止请求，不会静默上传。

API Key 不会写入 `config.toml`、SQLite 或日志。GUI 使用 Windows 的当前用户加密存储保存 Key；若把工作区复制到另一台电脑或换用另一 Windows 账号，需要重新输入一次。需要撤销时，在相同配置编号下点击 **清除已保存密钥**。

“高级选项：从环境变量读取密钥”只提供给已有自动化配置的用户，普通使用不需要打开或设置 PowerShell。

### 上传边界与成本

- 上传内容仅限位于工作区 `previews` 目录的受控预览图，以及用于分析的匿名质量指标，不包含原始照片、源路径、原始 hash 或 sidecar 原文。
- 费用、用量限制和模型权限由对应 Provider 账号决定。可在 `config.toml` 的 `[ai.limits]` 设置请求、预览字节和估算成本上限。
- 若隐私最小化、预算或外传限制比自动标签更重要，应选择离线演示模型或 loopback Provider，不要启用云端。

## 6. 人工审核页面

“3. 审核”会打开另一个同样仅限 `127.0.0.1` 的标签页。审核页可：

- 按年份、月份、分类、处置状态和文件名/标签/描述筛选。
- 查看单张预览、AI 原因、置信度和本地质量分。
- 查看精确重复组或连拍组。
- 在分类下拉框和处置下拉框中选择人工结果，再点“保存人工决定”。
- 用“标记保留”快速设为 `KEEP`，或用“标记淘汰候选”设为 `REJECT_CANDIDATE`。
- 用上一页、下一页浏览结果，单页最多显示 100 项。

`REJECT_CANDIDATE` 的含义是“建议在输出中放入待审区域”，不是删除照片。当前 GUI 计划只会复制，
不会移动、改名或删除照片源。

## 7. 执行后、回滚与故障处理

### 记录事务 ID

真实复制成功后，结果框中的 `applied` 对象会包含 `transaction_id`、状态以及成功/失败计数。
将该 ID 保存到操作记录中。事务 ID 是精确回滚的凭据，不要猜测或混用不同工作区的 ID。

### 回滚一次复制

仅当你希望撤销该事务创建的输出副本时：

1. 点击 **诊断**，确认没有正在运行的操作或未解决错误。
2. 在“复制记录编号”填入执行结果中的编号。
3. 点击 **安全回滚**，并在弹出的二次确认中选择“确定”。
4. 阅读结果框中的已回滚和失败数量。

回滚针对可由事务日志和哈希验证的输出副本。若你在输出目录手工移动、修改或删除过文件，工具可能拒绝
部分回滚以避免删除无法确认归属的文件。此时保留结果信息，先备份输出目录，再使用“诊断”定位原因。

### 常见情况

| 现象 | 原因或处理 |
| --- | --- |
| `spt` 不是内部命令 | 使用 `.\.venv\Scripts\spt.exe`，或先激活 `.venv`。 |
| 浏览器未打开 | 从终端复制 `http://127.0.0.1:端口/` 到本机浏览器。 |
| 扫描失败 | 检查路径拼写、读取权限，以及工作区没有位于照片源/输出目录中。 |
| 预检不通过 | 不要执行。阅读结果框的 issue，处理空间、计划陈旧、输出目录或未完成事务问题后重新预检。 |
| 不小心点到真实复制或回滚 | 二次确认对话框中选择“取消”即可，不会触发文件变更。启用云端仍需输入 `ALLOW_CLOUD`。 |
| Gemini 准备失败 | 确认已保存云端授权、模型 ID 可用、API key 有效且网络可访问。错误不会显示 API key。 |
| GUI 被意外关闭 | 重启同一工作区，先点“诊断”；如有未完成事务，先处理诊断结果再重新计划或执行。 |

## 8. 卸载

先停止 GUI。若只想卸载程序运行环境、保留所有工作区和照片，删除下面这个**精确目录**即可：

```powershell
Remove-Item -Recurse -Force "F:\Projects\Smart-Photo-Triage\.venv"
```

这会删除 Python 虚拟环境和 `spt` 可执行入口，不会删除：

- `F:\Projects\Smart-Photo-Triage` 中的源码；
- `D:\SPT-Workspace` 中的工作区记录；
- 照片源；
- 输出目录及已复制的文件。

若未来要删除工作区，先确认不再需要其审核记录、计划、事务 ID 或回滚能力，再通过资源管理器将
`D:\SPT-Workspace` 移到回收站。不要把“卸载程序”与“删除工作区数据”混为一谈。

## 9. 重要限制

- GUI 是本地控制面板，不是云服务，也没有账号、共享链接或远程访问能力。
- 默认“准备与分析”使用离线 `FakeVisionProvider`。Gemini、OpenAI、Anthropic 或兼容 Provider 只有在路由引用、已保存 API Key 或环境变量可用且网络权限明确授权后才会联网。
- GUI 使用 Provider Registry 和两条独立路由，不支持把 Codex、Claude Code 这类开发 Agent 的凭据直接填入视觉模型配置。
- 当前 GUI 只生成 `COPY` 计划，不支持移动或删除照片源。
- 真正的文件写入仅发生在通过批准和预检后的“真正复制”，以及你明确确认的“安全回滚”。
